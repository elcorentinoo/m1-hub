────────────────────────────────────────────────────────────
  LE CLASSEMENT
────────────────────────────────────────────────────────────
lb.js réutilise ton projet Supabase existant (mêmes tables `scores`).
Les résultats du M1 sont CLOISONNÉS de ceux de la LP grâce à la
constante PROGRAM en haut de lb.js : chaque score est enregistré
avec le préfixe "M1 · ", et le classement ne lit que ces lignes-là.

  → Le classement M1 n'affiche que les résultats M1.
  → Le classement LP (ancien site) continue d'afficher les siens.
  → Aucune modification de base de données nécessaire.

Depuis la 5.1.0, deux classements :
  • « Qui complète le plus » : chaque appareil envoie, pour chaque
    cours, son pourcentage de complétion (lignes mode « Progression »,
    correct = %, total = 100, xp = leçons validées), seulement quand il
    change. Le classement fait la moyenne sur les cours listés dans
    COURS_M1, en haut de lb.js — une nouvelle matière = une ligne là.
  • « Meilleur taux de réussite » : bonnes réponses ÷ questions sur
    les tests finaux et séries enregistrés (20 questions minimum).

Si tu préfères un projet Supabase totalement dédié au Master,
remplace simplement `url` et `key` en haut de lb.js.

  AJOUTER UNE NOUVELLE MATIÈRE
────────────────────────────────────────────────────────────
1. Dépose le nouveau fichier .html de la matière dans ce dossier.

2. Ouvre index.html, trouve le tableau MATIERES et ajoute un bloc :

     {
       file:"nom_du_fichier.html",
       icon:"📑", color:"c-plum", badge:"Format du partiel",
       title:"Nom de la matière",
       desc:"Une phrase ou deux sur le contenu du cours.",
       tags:["Thème 1","Thème 2","Thème 3"],
       meta:"X leçons · test · mini-cas"
     },

   Couleurs disponibles : c-teal · c-amber · c-navy · c-plum · c-rust · c-gold

   Pour annoncer une matière pas encore prête, ajoute `soon:true`
   et retire `file:` → la carte s'affiche grisée "à venir".

3. Dans le fichier de la matière, vérifie que ces 3 lignes sont présentes
   (elles branchent la matière sur le classement) :
     • <a class="hublink" href="index.html">← Hub</a>   dans la topbar
     • <script src="lb.js"></script>                    avant le script principal
     • const SUBJECT_KEY = 'Nom de la matière';          en haut du script
     • l'appel LB.record({...}) à la fin de showResult()

────────────────────────────────────────────────────────────
  LA RESSOURCERIE — À FAIRE AVANT LA PREMIÈRE UTILISATION
────────────────────────────────────────────────────────────
La page ressourcerie.html a besoin d'une table ET d'un espace de
stockage dans ton projet Supabase. Ouvre le SQL Editor et lance
ce script UNE FOIS :

--------------------------------------------------------------
-- 1. La table des fiches descriptives
create table public.ressources (
  id bigint generated always as identity primary key,
  titre text not null,
  resume text,
  matiere text,
  mots_cles text,
  pseudo text not null,
  fichier_nom text not null,
  fichier_path text not null,
  fichier_type text,
  fichier_taille bigint,
  created_at timestamptz default now()
);

alter table public.ressources enable row level security;

create policy "ressources lecture" on public.ressources
  for select to anon using (true);
create policy "ressources ecriture" on public.ressources
  for insert to anon with check (true);
create policy "ressources suppression" on public.ressources
  for delete to anon using (true);

-- 2. L'espace de stockage des fichiers
insert into storage.buckets (id, name, public)
values ('ressources', 'ressources', true)
on conflict (id) do nothing;

create policy "fichiers lecture" on storage.objects
  for select to anon using (bucket_id = 'ressources');
create policy "fichiers depot" on storage.objects
  for insert to anon with check (bucket_id = 'ressources');
create policy "fichiers suppression" on storage.objects
  for delete to anon using (bucket_id = 'ressources');
--------------------------------------------------------------

Message attendu : « Success. No rows returned ». C'est normal.

COMMENT FONCTIONNE L'ANALYSE
  Tout se passe dans le navigateur du déposant, sans serveur ni
  clé API : aucun frais, et le fichier ne part nulle part avant
  qu'il valide.
    • PDF  → texte extrait avec PDF.js (12 premières pages)
    • DOCX → texte extrait avec Mammoth
    • TXT / MD / CSV → lus directement
    • PPTX / XLSX / images → pas d'extraction : saisie manuelle
  Le résumé est EXTRACTIF : il sélectionne les 3 phrases les plus
  représentatives du document, il ne les reformule pas. Le titre,
  le résumé et les mots-clés restent modifiables avant publication.

  Pour passer à un vrai résumé rédigé par une IA, il faudrait une
  fonction Netlify (dossier netlify/functions) gardant une clé API
  côté serveur — l'API est facturée à l'usage.

LIMITES À CONNAÎTRE
  • Le dépôt est libre et sans authentification réelle : le pseudo
    n'est pas vérifié. Chacun ne peut supprimer que ses propres
    dépôts, mais rien n'empêche quelqu'un de reprendre un pseudo.
  • Les fichiers sont PUBLICS : toute personne ayant le lien direct
    peut les télécharger.
  • Attention aux droits d'auteur : les supports de cours appartiennent
    aux enseignants. Un partage entre étudiants d'une même promo est
    une chose, une diffusion publique en est une autre.
  • Plan gratuit Supabase : 1 Go de stockage.

────────────────────────────────────────────────────────────
  NAVIGATION ET THÈME (ui.css + ui.js)
────────────────────────────────────────────────────────────
Ces deux fichiers sont chargés par TOUTES les pages. Ne les
renomme pas et ne les supprime pas.

LA NAVIGATION
  Chaque page contient <span id="nav-slot"></span> dans sa barre
  du haut ; ui.js y place le bouton ☰ Menu et le bouton de thème.
  Le menu s'ouvre en tiroir sur la droite et liste : le Hub, les
  trois matières, la Ressourcerie, le Glossaire et le Classement.

  → Pour ajouter une matière au menu, édite le tableau PAGES en
    haut de ui.js (une ligne par entrée).

LE THÈME
  Depuis la 2.1.0, le site est entièrement sombre : il n'y a plus
  de mode clair, plus de sélecteur dans le menu et plus de bascule
  horaire. La palette complète tient dans theme.css (bloc « PALETTE »)
  et s'applique à toutes les pages ; l'impression des fiches, elle,
  reste en noir sur blanc.

  Les schémas SVG des cours utilisent des variables de couleur :
  ils s'adaptent automatiquement au thème. Si tu ajoutes un schéma,
  utilise var(--teal), var(--navy-soft)… plutôt qu'un code
  hexadécimal, sinon il restera figé en mode sombre.

LE GLOSSAIRE
  Les entrées sont dans le tableau G de glossaire.html :
    {s:'SIGLE', d:'Développé', m:'mp', l:'l4', t:'Définition',
     c:'à ne pas confondre avec…'}
    • m : mp / pd / mk (la matière)
    • l : l'identifiant de la leçon (l1 à l11)
    • c : facultatif, affiche un avertissement rouge
  Le lien « Voir la leçon » ouvre le cours directement à la bonne
  leçon grâce à une ancre (#l4) gérée par ui.js.

  VERSIONS DU SITE
────────────────────────────────────────────────────────────
Le site fonctionne hors ligne : les navigateurs gardent donc
l'ancienne version en cache. Le numéro de version sert à leur
signaler qu'il faut se mettre à jour.

  DEUX ENDROITS, TOUJOURS LA MÊME VALEUR :
      sw.js  ligne 16   const VERSION = '1.0.0';
      ui.js  ligne 13   const VERSION_APP = '1.0.0';

CONVENTION
      MAJEURE   refonte, fonctionnalité structurante
                (1.0.0 → 2.0.0)
      MINEURE   nouvelle matière, nouvelle page
                (1.0.0 → 1.1.0)
      CORRECTIF correction, ajustement, contenu retouché
                (1.0.0 → 1.0.1)

Chaque version MAJEURE porte un nom de code monétaire, clin
d'œil au Master Monnaie Banque : Écu, Denier, Louis, Franc,
Livre, Sesterce, Florin, Ducat…

La version s'affiche en bas du menu de navigation.

  MODE HORS LIGNE
────────────────────────────────────────────────────────────
  • La PREMIÈRE visite doit se faire EN LIGNE : le site met
    alors en cache ses pages, ses polices et ses bibliothèques.
  • Ensuite, fonctionnent sans réseau : les 3 cours, les quiz,
    les tests, le générateur de calculs, le glossaire, la
    révision, les statistiques.
  • Nécessitent le réseau : le classement et la ressourcerie
    (données partagées). Un bandeau prévient quand la connexion
    manque.
  • Installation : sur Android, menu ⋮ → « Installer l'application ».
    Sur iPhone, bouton Partager → « Sur l'écran d'accueil ».

────────────────────────────────────────────────────────────
  RÉVISION ESPACÉE (revision.html)
────────────────────────────────────────────────────────────
Paliers : 1, 3, 7, 16, 35 puis 75 jours. Une bonne réponse fait
monter d'un cran, une erreur ramène au début (à revoir le jour
même). Trois modes : révision espacée, flashcards (sigles du
glossaire, auto-évaluation) et tirage au hasard.

  ⚠️ banque.js est un fichier GÉNÉRÉ à partir des questions des
  trois cours et du glossaire. Si tu ajoutes ou modifies des
  questions dans un cours, il faut le régénérer — demande-le moi,
  sinon la révision travaillera sur l'ancienne version.

────────────────────────────────────────────────────────────
  AUTRES NOUVEAUTÉS
────────────────────────────────────────────────────────────
  • Recherche globale : Ctrl+K (ou ⌘+K), ou le bouton 🔍.
    Indexe les pages, les leçons et les 93 sigles.
  • Impression : bouton « 🖨️ Fiche » en bas à gauche d'un cours.
    Imprime la leçon affichée, sans les menus ni les quiz.
  • Progression : enregistrée sur l'appareil (localStorage).
    Elle ne suit pas d'un appareil à l'autre et ne survit pas à
    une navigation privée.

  LE SIMULATEUR FISCAL (es_banque.html)
────────────────────────────────────────────────────────────
Barèmes codés, tous vérifiés contre les exemples officiels :

  Art. 990 I — primes versées AVANT 70 ans
    abattement 152 500 € PAR BÉNÉFICIAIRE
    20 % sur la fraction taxable jusqu'à 700 000 €
    31,25 % au-delà (soit à partir de 852 500 € reçus)

  Art. 757 B — primes versées APRÈS 70 ans
    abattement 30 500 € GLOBAL, réparti au prorata des parts
    assiette = les PRIMES SEULES (les gains sont exonérés)
    puis barème progressif de l'art. 777 selon le lien

  Art. 777 — barème ligne directe (inchangé depuis 2011)
    5 % jusqu'à 8 072 € · 10 % · 15 % · 20 % jusqu'à 552 324 €
    30 % · 40 % · 45 % au-delà de 1 805 677 €
    abattements art. 779 : 100 000 € enfant · 15 932 € frère/sœur
    7 967 € neveu/nièce · 1 594 € à défaut
    conjoint et PACS exonérés (loi TEPA 2007)

HYPOTHÈSES DU SIMULATEUR (affichées dans la page)
  • bénéficiaires à parts égales
  • capital réparti entre les deux régimes au prorata des primes
  • l'abattement personnel n'est appliqué au 757 B que s'il est
    déclaré disponible (en pratique la succession le consomme
    en premier)
  • les prélèvements sociaux sur les gains d'UC non encore
    prélevés ne sont pas intégrés

────────────────────────────────────────────────────────────
  FISCALITÉ 2026 — CE QUI A CHANGÉ
────────────────────────────────────────────────────────────
LFSS 2026 (article 12) : la CSG sur les revenus du capital passe
de 9,2 % à 10,6 %.

  Prélèvements sociaux à 18,6 %, flat-tax à 31,4 % :
    dividendes, intérêts, plus-values mobilières, comptes-titres,
    livrets fiscalisés, DAT, PEA, PER, épargne salariale, crypto

  Maintenus à 17,2 %, flat-tax à 30 % (exceptions explicites) :
    assurance vie, PEL, CEL, PEP, revenus fonciers,
    plus-values immobilières

  Toujours exonérés : Livret A, LDDS, LEP, Livret Jeune

La transmission n'est pas touchée : ni l'article 990 I, ni le
757 B, ni le barème des droits de succession n'ont été modifiés.
